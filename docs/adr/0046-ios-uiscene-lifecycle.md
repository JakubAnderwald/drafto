# 0046 — iOS Adopts the UIScene Lifecycle

- **Status**: Accepted
- **Date**: 2026-10-10
- **Authors**: Jakub Anderwald, Claude

## Context

The Mac mini that builds the iOS app moved to Xcode 27 (iOS 27 SDK) on 2026-10-04. On 2026-10-10 TestFlight builds 1.4.1 (44) and 1.4.2 (45) both crashed on every launch on an iPhone 12 running iOS 27.0.1. The device crash log shows `EXC_BREAKPOINT` on the main thread in UIKit's `___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption_block_invoke`, called from `-[UIApplication workspace:didCreateScene:withTransitionContext:completion:]`. No Drafto code is on the stack.

iOS 27 stops an app that is linked against the iOS 27 SDK and has not adopted the UIScene lifecycle. The app's `ios/` project is generated by `expo prebuild` from Expo's AppDelegate template. That template has no `UIApplicationSceneManifest` and creates the window in `application(_:didFinishLaunchingWithOptions:)`, which is the legacy lifecycle. Neither Expo SDK 55 (installed) nor SDK 57 (latest at the time) adopts scenes, and React Native 0.83 has no switch for it.

The same builds run on iOS 26, including the iOS 26.5 simulator. The crash only shows up on iOS 27.

## Decision

Adopt the UIScene lifecycle through a config plugin, `apps/mobile/plugins/with-ios-scene-lifecycle.js`, so it survives `expo prebuild --clean`. On every prebuild it does three things:

- Info.plist gets a single-window `UIApplicationSceneManifest` whose delegate is `$(PRODUCT_MODULE_NAME).SceneDelegate`.
- `AppDelegate.swift` keeps creating the React Native factory but no longer creates the window or starts React Native. It stores its launch options instead.
- A generated `SceneDelegate.swift` is added to the app target. It creates the window from the scene and starts React Native in it, with launch options extended with the cold-start URL (`.url`) and universal link (`.userActivityDictionary`) from `UIScene.ConnectionOptions`, which is where `RCTLinkingManager.getInitialURL` reads them. It also forwards every URL (`scene(_:openURLContexts:)`) and user activity (`scene(_:continue:)`), including the cold-start ones, to the AppDelegate callbacks. Under scenes iOS no longer calls those callbacks, but RCTLinkingManager and Expo's subscribers still listen there. expo-linking's subscriber is what fills `getLinkingURL`, which expo-router reads.

The AppDelegate edits are anchored on the generated template and throw when an anchor is missing. A template change then fails `expo prebuild` loudly rather than shipping an app that crashes on launch.

## Consequences

- **Positive**:
  - The iOS app launches on iOS 27 when built with Xcode 27.
  - The scene lifecycle is also what Apple requires going forward.
- **Negative**:
  - The plugin edits Expo's generated AppDelegate by string anchors, so every Expo SDK upgrade must re-check it. Prebuild fails if the anchors move, which is intended.
  - Cold-start link handling now lives in `SceneDelegate`, so a regression there would show up as deep links (password reset, Google sign-in callback, universal links) that do nothing on a cold start. `apps/mobile/e2e/06-forgot-password.yaml` and the manual checks in `docs/architecture/testing.md` cover the reset link.
  - Every iOS build from 2026-10-04 until this change (mobile 1.4.1 and 1.4.2) crashes on iOS 27.
- **Neutral**:
  - Google Sign-In presents through `RCTPresentedViewController`, which finds the key window through the connected scenes, and it handles its own callback with `ASWebAuthenticationSession`. It needs no AppDelegate URL hook.
  - Remove the plugin once Expo's template adopts scenes.

## Alternatives Considered

1. **Build iOS with Xcode 26 (iOS 26 SDK).** Apps linked against the iOS 26 SDK are not stopped on iOS 27. This is only a stopgap until Apple requires the iOS 27 SDK for App Store submissions. It would also need a second Xcode installed with an Apple ID download, and the lanes would have to pin `DEVELOPER_DIR`. Rejected.
2. **Upgrade the Expo SDK.** SDK 57, the latest, still ships the legacy AppDelegate template, so an upgrade alone doesn't fix this and brings a large unrelated change. Rejected.
3. **Commit the `ios/` folder and hand-edit it.** The project regenerates `ios/` with `expo prebuild --clean` in every release lane. Rejected.
